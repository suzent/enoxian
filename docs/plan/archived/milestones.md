# Completed Milestones Archive

This archive records completed roadmap milestones so the main
[roadmap.md](../roadmap.md) can stay focused on current work.

## M1 — Workspace Folders

**Status:** Complete

Each circle has a named, visible workspace directory. The default location is
`~/enoxian/<circle-name>/`, with `--dir` support for custom workspaces.

## M2 — Secure Network

**Status:** Complete

Circle PSKs are enforced at the TCP transport layer with `libp2p::pnet`.
Mismatched circles fail before Noise negotiation.

Completed work:

- PSK applied to daemon swarms.
- PSK applied to `enox enter` connectivity checks.
- Cross-circle rejection verified.

## M3 — Live P2P Sync

**Status:** Complete

`/enoxian/sync/1.0.0` runs y-sync over libp2p streams. Peers exchange state
vectors, apply CRDT updates, flush received updates to disk, and recover from
lag by sending full state.

Completed work:

- libp2p stream behavior added.
- Deadlock-free sync handshake implemented.
- Local updates forwarded through `all_updates`.
- Peer updates applied with `"p2p"` origin to prevent echo loops.
- Startup preload and post-handshake full-state push added.
- CRDT state persisted across restarts.

## M4 — Circle Lifecycle

**Status:** Complete

The daemon can manage multiple circles and start/stop individual circles without
restarting the whole process.

Completed work:

- Per-circle `CancellationToken`.
- `enox disable`, `enox enable`, and `enox leave`.
- `POST /circles/<id>/stop` and `/start`.
- Hot-reload for newly enabled circles.

## M5 — Presence

**Status:** Complete

Presence is stored in the control CRDT and replicated between peers.

Completed work:

- Hostname-based agent IDs with override support.
- Heartbeat updates every 30 seconds.
- Immediate offline state on clean shutdown and disconnect.
- `enox who` last-seen display.

## M6 — Admin And Member Management

**Status:** Complete

Circle admins can sign membership operations. The admin private key remains on
the creator machine; the public key is embedded in invites.

Completed work:

- Admin keypair generated by `enox init`.
- Admin public key carried by invite links.
- Member list stored in the control CRDT.
- `enox member list/add/remove/promote/pending/approve/reject`.
- Pending join queue.
- Daemon auto-signs local frontend operations when `admin.key` is present.
- Stale pending and ghost member cleanup.

## M7 — CLI Completeness

**Status:** Complete

The CLI covers the main daemon and circle workflows.

Completed work:

- Task creation command.
- Task claim/done commands.
- Circle listing and lifecycle commands.
- Watch, status, who, chat, and member commands.

## M8 — File Sync Hardening

**Status:** Complete

The file sync path handles startup state, atomic-save behavior, deletion,
conflict copies, and session metadata.

Completed work:

- Startup workspace preload.
- CRDT state persistence.
- File deletion propagation.
- Temp and hidden file filtering.
- macOS atomic-save handling.
- Session ID exchange on reconnect.
- Divergence detection using state vectors.
- Conflict copies written as `<file>.conflict.<agent_id>`.
- `enox status` shows unresolved conflicts.

## M9 — Chat

**Status:** Complete

Chat is stored in the control CRDT and replicated through the existing sync
path.

Completed work:

- Chat message data model.
- `GET/POST /api/chat`.
- Chat SSE stream.
- `enox chat`, `enox chat --follow`, and `enox say`.
- `@mention` parsing emits agent wake events.

## M10 — Frontend

**Status:** Complete

`enoxd` serves a React frontend at `/app`.

Completed work:

- Circle selector.
- Presence panel.
- File tree.
- CodeMirror editor using Yjs.
- Remote cursors and awareness labels.
- Task queue.
- Chat panel.
- Member management UI.
- Production build through `build.rs`.
- `enox open`.

## M11 — MLS Membership And Tombstone Sync Gate

**Status:** Complete

MLS tracks group membership and prepares the future content-encryption layer.
The transport PSK remains stable. Removed peers are rejected by the
`mls_removed` sync gate before CRDT data is exchanged.

Completed work:

- `openmls` integration.
- MLS group creation at circle init.
- KeyPackage publishing.
- Welcome delivery and consumption.
- Serial commit watcher.
- Pending member approval flow.
- Remove commit broadcast.
- `mls_removed` tombstone map.
- Sync gate in `src/network/sync.rs`.

## M12 — WAN Support

**Status:** Complete

enoxian supports direct peer addresses, circuit relay, DCUtR, and public
bootstrap rendezvous servers.

Completed work:

- Relay client and relay server behavior.
- DCUtR hole punching.
- QUIC transport leg for bootstrap/rendezvous.
- `enoxd --bootstrap` mode.
- Stable bootstrap keypair.
- Relay and rendezvous addresses in config and invites.
- `enox invite` auto-embeds connectivity hints.
- `GET /api/status` exposes P2P address metadata.
