# Completed Milestones Archive

This archive records completed roadmap milestones so the main
[roadmap.md](../roadmap.md) can stay focused on current work.

## M1 — Workspace Folders

**Status:** Complete

Each circle has a named, visible workspace directory. The default location is
`~/enoxian/<circle-name>/`, with `--dir` support for custom workspaces.

## M2 — Secure Network

**Status:** Complete

Circle PSKs are enforced at the TCP transport layer with `libp2p::pnet`.
Mismatched circles fail before Noise negotiation.

Completed work:

- PSK applied to daemon swarms.
- PSK applied to `enox enter` connectivity checks.
- Cross-circle rejection verified.

## M3 — Live P2P Sync

**Status:** Complete

`/enoxian/sync/1.0.0` runs y-sync over libp2p streams. Peers exchange state
vectors, apply CRDT updates, flush received updates to disk, and recover from
lag by sending full state.

Completed work:

- libp2p stream behavior added.
- Deadlock-free sync handshake implemented.
- Local updates forwarded through `all_updates`.
- Peer updates applied with `"p2p"` origin to prevent echo loops.
- Startup preload and post-handshake full-state push added.
- CRDT state persisted across restarts.

## M4 — Circle Lifecycle

**Status:** Complete

The daemon can manage multiple circles and start/stop individual circles without
restarting the whole process.

Completed work:

- Per-circle `CancellationToken`.
- `enox disable`, `enox enable`, and `enox leave`.
- `POST /circles/<id>/stop` and `/start`.
- Hot-reload for newly enabled circles.

## M5 — Presence

**Status:** Complete

Presence is stored in the control CRDT and replicated between peers.

Completed work:

- Hostname-based agent IDs with override support.
- Heartbeat updates every 30 seconds.
- Immediate offline state on clean shutdown and disconnect.
- `enox who` last-seen display.

## M6 — Admin And Member Management

**Status:** Complete

Circle admins can sign membership operations. The admin private key remains on
the creator machine; the public key is embedded in invites.

Completed work:

- Admin keypair generated by `enox init`.
- Admin public key carried by invite links.
- Member list stored in the control CRDT.
- `enox member list/add/remove/promote/pending/approve/reject`.
- Pending join queue.
- Daemon auto-signs local frontend operations when `admin.key` is present.
- Stale pending and ghost member cleanup.

## M7 — CLI Completeness

**Status:** Complete

The CLI covers the main daemon and circle workflows.

Completed work:

## M8 — File Sync Hardening

**Status:** Complete

The file sync path handles startup state, atomic-save behavior, deletion,
conflict copies, and session metadata.

Completed work:

## M14 — Local Workspace Proposals And Agent Execution

**Status:** Complete (core). Only an optional sandbox/fork mode is deferred.

An agent-agnostic proposal layer: local agents, editors, scripts, and tools make
arbitrary filesystem changes in the normal workspace, and enoxian captures them
as reviewable proposals. Extended during development into a full agent-execution
layer over the Agent Client Protocol. Verified end to end against real ACP agents
(Claude Code, Codex). User guide: [../../agents.md](../../guide/agents.md); design:
[../agent-workspaces.md](../agent-workspaces.md).

Completed work:

- Foundation: content-addressed blob store, snapshot manifest format, and a
  snapshot journal capturing before-blobs for ambient edits.
  (`src/proposal/{blob,snapshot,journal}.rs`)
- Ambient proposal flow: dirty grouping by idle window, snapshot diff, three-way
  merge against canonical state, and cross-device replication via the proposal
  pull protocol. (`src/proposal/{engine,diff,merge,sync}.rs`)
- CLI: `enox proposal list/show/accept/reject/revert`; frontend review/history
  view. (`src/commands/proposals.rs`, `frontend/.../ProposalsTab.tsx`)
- Sessions and attribution: local change session model with confidence levels;
  `enox session start/finish` (claimed session mode). (`src/proposal/session.rs`,
  `src/commands/session.rs`)
- Local reaction layer: agent wake-ups are plain chat mentions with a per-device
  push/pull policy; the imperative circle-trigger was removed (a replicated
  command that lets a remote member push execution is the dangerous framing).
  (`src/agent/reaction.rs`, `src/agent/config.rs`)
- Local execution: `enox agent run`; ACP driver (`session/new`/`load`/`prompt`,
  fs + permission callbacks) and an argv fallback driver.
  (`src/agent/{driver,acp,spawn}.rs`)
- Acceptance policy: auto-accept for locally-initiated runs, pending review for
  remote-member-initiated runs. (`src/proposal/policy.rs`)
- Agent experience: ACP session memory (resume per circle+agent), world-context
  injection, hierarchical `@owner/device/agent` mentions with `@` autocomplete
  and atomic chips, agents advertising their configured agents, agent config via
  CLI and frontend, process reaping, and mention-replay safety (durable dedup +
  `ts` cutoff so a restart never re-triggers past mentions; agent replies never
  wake other agents).
  (`src/agent/{memory,context,mention,handled}.rs`, `src/api/agent_config.rs`,
  `src/commands/agent.rs`, `frontend/.../MentionInput.tsx`)
